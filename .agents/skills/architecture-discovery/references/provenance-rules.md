# Provenance rules

Preserve enough information to re-find evidence for every material architectural claim.

Record when available:
- Evidence ID
- Claim
- Source type and identifier
- Document section, or repository/path/line/commit
- Freshness
- Confidence
- Status
- Related requirement or question

Do not impose one universal source hierarchy. Authority depends on the claim. Preserve documentation-versus-implementation conflicts rather than silently reconciling them.

A recent file timestamp does not prove semantic freshness. If evidence is missing, create a Knowledge Gap.
